# README Studio — Promotional Video Prompt

A ready-to-use creative brief and generation prompt for a short product film about README Studio.

Tagline: **A better way to build your README.**

> Use the master prompt with a text-to-video tool, or as a director's brief for a human editor. The strongest result comes from combining generated atmosphere shots with real screen recordings of the app. Add final UI text, logo and typography in post-production so no generated text is distorted.

---

## 1. Copy-paste master prompt

```text
Create a polished 32-second promotional film for README Studio, a calm, local-first Markdown workspace for building project README files.

Creative direction:
- Apple-inspired product film with a developer-tool sensibility.
- Restrained, premium and human. Confident, not hyped.
- Mostly light surfaces, generous negative space and precise details.
- The interface should feel fast, quiet and satisfying to use.
- Make the viewer feel that writing documentation can be focused instead of chaotic.

Palette:
- Background: #F5F5F7
- Surfaces: #FFFFFF
- Primary text: #1D1D1F
- Secondary text: #86868B
- Borders: #E5E5EA
- Accent: #3478F6
- Success: #248A3D

Strictly avoid:
- purple, violet, pink or magenta
- neon colors, flashy gradients, glassmorphism
- exaggerated lens flares, floating 3D icons or sci-fi interfaces
- childish visuals, emojis, memes or stock-photo office clichés
- fake testimonials, invented metrics, fake repository stars
- distorted logos or unreadable generated UI text

Format:
- 16:9, 3840 x 2160, 30 fps, cinematic but crisp
- Soft natural light, subtle depth of field, realistic materials
- Camera movement should be calm and intentional: slow push-ins, gentle lateral moves, macro details

Storyboard:
0–4 seconds
A quiet light-gray desk surface. A closed laptop or a blank sheet of paper. Natural morning light moves slowly across the frame. The camera pushes in as the screen wakes to a bright, minimal workspace. A soft click. Keep the moment tactile and quiet.

4–10 seconds
Reveal README Studio: compact navigation sidebar on the left, a focused Markdown editor in the center and a live GitHub-style preview on the right. A cursor types a project title and a short description. The preview updates instantly. Show the words "Project title" and "Live preview" rendered clearly in the interface, or leave the UI clean for a real screen recording replacement in post.

10–17 seconds
Macro close-ups of writing and formatting. A heading becomes bold. A feature list forms. A Markdown table renders in the preview with perfect alignment. A subtle blue highlight moves over the toolbar. The editor looks calm and uncluttered: white surface, fine borders, generous spacing.

17–23 seconds
The AI assistant panel slides in from the right. The user types a short natural-language instruction. The README updates live while the preview stays in sync. A quality score moves upward. The mood is collaborative and controlled, never chaotic or magical.

23–27 seconds
The user finishes and clicks Export README.md. A clean file icon moves toward a repository-style page. The README is rendered beautifully on a light documentation page. No invented stars, users or performance numbers.

27–32 seconds
End on a calm light canvas with a large, crisp wordmark "Readme.studio" and the line "A better way to build your README." Hold for one second. Finish on the accent-blue call-to-action button.

Typography:
- Modern system sans-serif, tight tracking, generous line height
- Small labels in uppercase with wide tracking
- No decorative fonts

Sound:
- Quiet room tone, soft keyboard clicks, subtle UI ticks
- Minimal ambient electronic bed with a warm low pulse and a gentle piano motif
- No heavy whooshes, no dubstep, no crowd noise, no robotic voice
- Music should resolve softly on the end card

Motion:
- Smooth 24–30 fps feel
- Subtle cursor movement and realistic UI state changes
- No camera shake, no fast spinning transitions
- Use match cuts between the editor, the preview and the exported file

End card:
Large "Readme.studio" wordmark on #F5F5F7, centered. Below it: "A better way to build your README." A small accent-blue button reading "Start building". Leave space for a real product URL to be added in post-production.

Important:
The app UI must look like a real desktop application, not a fantasy hologram. Prefer clean screen replacement in post-production. Do not generate fake code that looks impossible or fake documentation with legible false claims. The final result should feel like a real product a thoughtful developer would use every day.
```

Tone: calm, warm, confident, lightly paced. Avoid an announcer voice and avoid exaggerated enthusiasm.

README Studio.

---

## 9. Production notes

1. Record the actual app at 1440px or wider with a clean document. Use real UI for the main interface shots.
2. Replace generated screen text in post-production. Do not rely on AI video to render readable UI copy.
3. Use the real wordmark from `logo/Sans titre.png` on the end card. Crop it cleanly with transparent or light background and preserve its proportions.
4. Add a real product URL only when one exists. Do not invent one.
5. Export a 16:9 master with captions, a 9:16 cutdown and a still poster frame for the first frame.
6. Loudness target for social: approximately −14 LUFS integrated, with subtitles burned in for silent autoplay.
7. Preferred file names:
   - `readme-studio-promo-16x9.mp4`
   - `readme-studio-promo-9x16.mp4`
   - `readme-studio-promo-poster.png`
